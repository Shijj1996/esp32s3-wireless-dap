# 无线 CMSIS-DAP 手动操作手册

> 适用环境：ESP32-S3 盒子 + Windows 热点 `ESP32-DAP` + STM32CubeIDE 1.19 + usbip-win2 0.9.8.1
>
> 本文所有命令都在**普通 PowerShell**（不需要管理员）里执行，只有标注「需管理员」的步骤除外。

---

## 0. 整体链路

```
STM32CubeIDE (GDB)
      │ localhost:3333
      ▼
   OpenOCD  ── CMSIS-DAP v2 (WinUSB)
      │
      ▼
 usbip-win2 虚拟主机控制器
      │ TCP 3240
      ▼
 ESP32-S3 盒子 (STA, 192.168.137.50)
      │ SPI/GPIO 位操作
      ▼
 STM32F1 (SWDIO=GPIO11, SWCLK=GPIO12)
```

| 项目 | 值 |
|---|---|
| 盒子 IP | `192.168.137.50`（静态） |
| USBIP 端口 | `3240` |
| BusID | `1-1` |
| VID:PID | `0xc251:0xf00a` |
| GDB 端口 | `3333` |
| Telnet 端口 | `4444` |
| 推荐 SWD 速率 | **300 kHz** |

## 1. 前提检查

### 1.1 电脑热点必须开着

Windows「移动热点」：SSID `ESP32-DAP`，密码 `12345678`，**2.4 GHz**。

### 1.2 盒子已连上

```powershell
Test-NetConnection 192.168.137.50 -Port 3240 -InformationLevel Quiet
```

返回 `True` 才算通。不通的话：盒子没上电 / 没连热点 / 电脑热点没开。

> 盒子启动 1~2 秒即可连上，串口日志会打印
> `wireless DAP ready at 192.168.137.50:3240`。

## 2. 挂载（usbip attach）

### 2.1 先确认远端能看到设备

```powershell
& 'C:\Program Files\USBip\usbip.exe' list -r 192.168.137.50
```

应看到：

```
    1-1    : Keil Software, Inc. : unknown product (c251:f00a)
```

### 2.2 挂载

```powershell
& 'C:\Program Files\USBip\usbip.exe' attach -r 192.168.137.50 -b 1-1 --receive-mode low-latency
```

> **`--receive-mode low-latency` 必须加！**
> usbip-win2 默认的 `zero-copy` 模式会把 URB 串行化：一个 bulk-IN 读挂起时
> bulk-OUT 写发不出去，CMSIS-DAP 的「写命令 + 读应答」直接死锁，表现为
> `busy command USB transfer` / `CMD_INFO failed`。

输出 `successfully attached to port 1` 即成功。

### 2.3 确认挂载结果

```powershell
# 端口状态
& 'C:\Program Files\USBip\usbip.exe' port

# Windows 设备节点（应为 OK / Wireless ESP CMSIS-DAP）
Get-PnpDevice | Where-Object { $_.InstanceId -match 'VID_C251' } |
    Select-Object Status, FriendlyName, InstanceId
```

期望：

```
Port 01: device in use at High Speed(480Mbps)
         -> usbip://192.168.137.50:3240/1-1

Status  FriendlyName            InstanceId
OK      Wireless ESP CMSIS-DAP  USB\VID_C251&PID_F00A\1234
```

### 2.4 用脚本一步完成（可选）

```powershell
.\tools\attach-dap.ps1
```

## 3. 启动 OpenOCD

### 3.0 一条命令搞定（推荐）

`serve` 现在是**默认模式**，它会自动完成「检测 → 挂载 → 启动 OpenOCD」：

```powershell
.\tools\stm32cubeide-dap.ps1
```

指定目标/速率：

```powershell
.\tools\stm32cubeide-dap.ps1 -Target stm32f1x -Speed 300
```

运行时输出：

```
[+] DAP 已挂载（USB\VID_C251&PID_F00A\1234）

==================================================
  无线 DAP 已就绪
--------------------------------------------------
  设备   : Wireless ESP CMSIS-DAP
  GDB    : localhost:3333
  Telnet : localhost:4444
  目标   : stm32f1x @ 300 kHz
  退出   : Ctrl+C
==================================================
```

它依次做的事：

1. **检测**：查 `VID_C251` 设备节点、`IP:3240`、`usbip list`、`usbip port`
2. **挂载**：还没挂就 `attach --receive-mode low-latency`，并等最多 15 秒
3. **防重复**：3333/4444 已被占用时直接报错退出，不会起第二个 OpenOCD
4. **启动 OpenOCD**：GDB 3333 / telnet 4444 / tcl 6666

一旦看到 `Listening on port 3333`，就可以去 CubeIDE 里连了。

### 3.1 手动命令（排查用）

```powershell
$ocd = 'D:\STM32CubeIDE_1.19.0\STM32CubeIDE\plugins\com.st.stm32cube.ide.mcu.externaltools.openocd.win32_2.4.200.202505051030\tools\bin\openocd.exe'
$scripts = 'D:\STM32CubeIDE_1.19.0\STM32CubeIDE\plugins\com.st.stm32cube.ide.mcu.debug.openocd_2.3.100.202501240831\resources\openocd\st_scripts'

& $ocd -s $scripts `
   -f "interface/cmsis-dap.cfg" `
   -c "cmsis-dap vid_pid 0xc251 0xf00a" `
   -f "target/stm32f1x.cfg" `
   -c "adapter speed 300" `
   -c "gdb_port 3333" -c "telnet_port 4444" -c "tcl_port 6666"
```

> 这个进程会一直占着窗口，**关掉窗口就等于停服务**。

### 3.2 脚本的其它模式

```powershell
.\tools\stm32cubeide-dap.ps1 -Mode status    # 只检查，不做动作
.\tools\stm32cubeide-dap.ps1 -Mode attach    # 只挂载
.\tools\stm32cubeide-dap.ps1 -Mode serve     # 检测+挂载+起服务（默认）
.\tools\stm32cubeide-dap.ps1 -Mode detach    # 卸载
.\tools\stm32cubeide-dap.ps1 -Mode flash -Elf <xxx.elf>
.\tools\stm32cubeide-dap.ps1 -Mode targets   # 列出可用 target
```

脚本会自动找 openocd、自动检查挂载状态，缺挂载会先挂上。

### 3.3 成功标志

```

## 4. CubeIDE 连接调试

CubeIDE 不能直接选 CMSIS-DAP 探针，用 **GDB Hardware Debugging** 连外部 GDB server。

> ⚠️ **现状（2026-11）：本节流程可用，但不稳定。**
>
> 已验证可靠的是**烧录**（§5）：写 3 KiB/s、校验 12 KiB/s、读 256 KB 无错误。
> 但 CubeIDE 的交互式调试（下载 + 断点 + 单步）会不定时掉链，典型报错：
>
> ```
> Polling target stm32f1x.cpu failed, trying to reexamine
> Error: Error connecting DP: cannot read IDR
> ```
>
> 根因在 OpenOCD 的 `reset init` 流程，不是 CubeIDE 配置错。日常建议：
> **用 §5 的脚本烧固件**，调试需求不强就到此为止；
> 想彻底修好，需要接 nRESET（§8）并启用 connect-under-reset。

### 4.1 新建配置

`Run → Debug Configurations…` → 左侧 **GDB Hardware Debugging** → 右键 **New**

### 4.2 Main 页

| 字段 | 值 |
|---|---|
| Name | `Wireless-DAP-F103` |
| C/C++ Application | 你的工程 `Debug\xxx.elf` |

### 4.3 Debugger 页（关键）

| 字段 | 值 |
|---|---|
| GDB Command | `arm-none-eabi-gdb` |
| JTAG Device | **Generic TCP/IP** |
| Host name | `localhost` |
| Port number | `3333` |

在 **Commands** 里加一行，消除心跳超时误报：

```
set remotetimeout 20
```

### 4.4 Startup 页（关键）

- **取消勾选 `Load executable`**
  （原因见 §6.1，CubeIDE 的下载流程会走 `reset init`，在我们这条链路上会失联）
- Reset 方式选 **`System reset`**，不要选 `Connect under reset`（nRESET 没接线时无效）

### 4.5 点 Debug

CubeIDE 会连上 3333、加载符号、停在 `main`。断点、单步、寄存器、内存窗口都正常。

## 5. 用脚本刷写固件

### 5.1 支持的文件格式

| 格式 | 说明 | 需要的参数 |
|---|---|---|
| `.elf` | CubeIDE / GCC 输出的可执行文件 | 无 |
| `.hex` | Intel HEX（Keil / IAR 常用） | 无 |
| `.bin` | 纯二进制 | **必须给 `-Address`**（默认 `0x08000000`） |

### 5.2 常用命令

```powershell
# ELF
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf

# HEX
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.hex

# BIN + 指定地址
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.bin -Address 0x08000000

# 烧完立即运行（默认是停在复位后的 halt）
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -Run

# 先整片擦除再烧
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -ChipErase

# 跳过校验（默认会校验）
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -NoVerify
```

实测输出：

```
[*] 烧录 D:\...\M06_01.elf
[*]   格式 elf
[*] 写入后校验
[*] 烧录后停在 halt
    wrote 19016 bytes from file ... in 6.440446s (2.883 KiB/s)
    verified 19016 bytes in 1.494135s (12.429 KiB/s)
[+] 烧录完成，目标停在复位后 halt 状态
```

### 5.3 复位方式（`-Reset`）

烧录完、以及 `serve` 模式下 CubeIDE 点复位，都按这个参数走。

| 值 | 含义 | 需要接线 | 说明 |
|---|---|---|---|
| **`sysresetreq`** | **软件复位**（写 AIRCR.SYSRESETREQ） | ❌ **不需要** | **默认值**，芯片自己走完整复位流程 |
| `srst` | 硬件复位脚（拉低 NRST） | ✅ 需要 nRESET 接线 | 目标程序关掉 SWD / 进低功耗时更可靠 |
| `vectreset` | 只复位 Cortex-M 内核 | ❌ 不需要 | 外设状态保留，只重启 CPU |
| `none` | 不复位 | ❌ 不需要 | 烧完只做 halt 或 resume，保持现场 |

```powershell
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -Reset sysresetreq   # 默认
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -Reset srst          # 需接 NRST
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -Reset vectreset
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.elf -Reset none
```

**当前硬件实际用的是哪个？**

本仓库 `S3Box` 分支上：`stm32f1x.cfg` 默认 `_CORE_RESET=0` → `cortex_m reset_config sysresetreq`，
而 nRESET（GPIO13）**尚未接到目标板 NRST**，所以实际生效的是**软件复位**。
想用硬件复位，先把 GPIO13 接到目标板 NRST，再用 `-Reset srst`。

底层对应的 OpenOCD 命令：

| -Reset | 下发的配置期命令 | 收尾动作（-Run / 默认） |
|---|---|---|
| `sysresetreq` | `reset_config none`<br>`cortex_m reset_config sysresetreq` | `reset run` / `reset halt` |
| `srst` | `reset_config srst_only srst_nogate`<br>`cortex_m reset_config srst` | `reset run` / `reset halt` |
| `vectreset` | `reset_config none`<br>`cortex_m reset_config vectreset` | `reset run` / `reset halt` |
| `none` | `reset_config none` | `resume` / `halt` |

#### 为什么要显式写 `reset_config none`

OpenOCD 的 `reset` 是**两层**的：

| 层 | 命令 | 作用 |
|---|---|---|
| adapter 层 | `reset_config ...` | 拉低 SRST 复位**脚** |
| core 层 | `cortex_m reset_config ...` | 写 AIRCR 触发 SYSRESETREQ / VECTRESET |

adapter 层默认是 `srst_only`。所以**即使选了 `sysresetreq`，OpenOCD 也会顺手去拉复位脚**——
之前 nRESET 没接线时看不出来（拉了也没反应），一旦把脚接上，这个副作用就真的生效，
行为开始依赖目标板的复位电路（RC 电容、复位芯片等），表现得像"sysresetreq 必须接复位脚"。

显式加 `reset_config none` 后，软件复位就是**纯软件复位，完全不碰任何引脚**，行为可预期。

> 实测（nRESET 未接线）：`sysresetreq` ✅ / `vectreset` ✅ / `srst` ❌（符合预期，没接线就不该成功）。

### 5.4 整片擦除

```powershell
.\tools\stm32cubeide-dap.ps1 -Mode erase
```

内部按目标系列选命令，例如 stm32f1x → `stm32f1x mass_erase 0`。
支持：F1 / F2 / F4 / F7 / L0 / L1 / L4 / G0 / G4 / WB / H7。

### 5.5 整片回读（保存为 bin）

```powershell
.\tools\stm32cubeide-dap.ps1 -Mode dump -DumpFile .\readback.bin
```

- 默认输出 `.\flash_dump.bin`
- **容量自动探测**（从 `flash banks` 读基地址和大小），不用手填
- 也可以强制指定长度：`-Size 0x40000`
- 256 KB 大约 20 秒（300 kHz）

```

[*]   基地址 0x08000000，长度 0x40000
[*] 回读整片 Flash → C:\...\readback.bin
    dumped 262144 bytes in 17.67s (14.49 KiB/s)
[+] 回读完成：262144 字节 (256 KB)
```

### 5.6 先干跑看命令（不碰硬件）

所有 flash / erase / dump 都支持 `-DryRun`，只打印将要执行的 OpenOCD 命令：

```powershell
.\tools\stm32cubeide-dap.ps1 -Mode flash -Image app.bin -Address 0x08000000 -ChipErase -DryRun
```

```

  -c "init; halt"

  -c "flash write_image erase {C:/.../app.bin} 0x08000000 bin"
  -c "reset halt"
  -c "shutdown"
```

### 5.7 脚本内部做的事（等价手动命令）

```powershell
& $ocd -s $scripts `
   -f "interface/cmsis-dap.cfg" `
   -c "cmsis-dap vid_pid 0xc251 0xf00a" `
   -f "target/stm32f1x.cfg" `
   -c "adapter speed 300" `
   -c "init; halt" `
   -c "flash write_image erase {你的文件}" `
   -c "verify_image {你的文件}" `
   -c "reset halt" `
   -c "shutdown"
```

> 路径里一律用 **正斜杠**：OpenOCD 的 Tcl 会把 `\f` `\n` `\t` 当转义吃掉。
> 脚本已经自动转换，手写命令时要注意。

### 5.8 为什么不用 `program`

`program` 内部会先执行 **`reset init`**，而我们这条链路上 reset-init 事件会导致：

```
Error: Error connecting DP: cannot read IDR
Error: [stm32f1x.cpu] Examination failed
```

`init` + `halt` + `flash write_image` 不触发它，实测稳定。

| 动作 | 速度 |
|---|---|
| 写入 | ≈ 3 KiB/s（19 KB 约 6 秒） |
| 校验 | ≈ 12 KiB/s |
| 读回 256 KB | ≈ 18 秒 |
| 全片擦除 | 1~2 秒 |

## 6. 已知问题与排障

### 6.1 `cannot read IDR` / `Examination failed`

这是最常见的报错，分几种情况：

| 触发场景 | 原因 | 处理 |
|---|---|---|
| 刚上电就连不上，`SWDIO/TMS = 0` | 目标没供电 / GND 没通 / 芯片损坏 | 量 3V3 和 GND |
| 下载时报 `failed erasing` 后连锁失败 | 走了 `reset init` | 改用 §5 的 `flash write_image` |
| Flash 是空的（全 0xFF） | 空片复位后 SP/PC 非法 → 内核 lockup | 先写一个合法镜像 |
| 目标程序关掉了 SWD | 代码里 `__HAL_AFIO_REMAP_SWJ_DISABLE()` 之类 | 接 nRESET，用 connect under reset |

### 6.2 `busy command USB transfer` / `CMD_INFO failed`

99% 是**挂载时没加 `--receive-mode low-latency`**。先 detach 再按 §2.2 重新挂。

### 6.3 端口僵死，`detach` / `attach` 卡住

设备重启过（比如盒子重新上电/重新烧录）后，驱动里的端口会变成僵尸状态。处理：

```powershell
# 1. 杀掉残留进程
Get-Process usbip -ErrorAction SilentlyContinue | Stop-Process -Force

# 2. 重置 VHCI 虚拟主机控制器（需管理员）
.\tools\reset-usbip.ps1
```

> ⚠️ `reset-usbip.ps1` 会「禁用再启用」`ROOT\USB\0000`。
> 如果它卡在「禁用」这一步，VHCI 会被留在禁用状态，`usbip port` 会报
> `VHCI device not found`。此时手动启用回来（需管理员）：
>
> ```powershell
> Start-Process powershell -Verb RunAs -ArgumentList '-NoProfile','-Command',
>   "Enable-PnpDevice -InstanceId 'ROOT\USB\0000' -Confirm:`$false"
> ```

### 6.4 速度：300 kHz 是稳定上限

| 请求 | 结果 |
|---|---|
| 200 / 300 kHz | ✅ 稳定 |
| 500 kHz | ⚠️ 时好时坏 |
| 700 kHz | ✅ 勉强，无余量 |
| 800 kHz+ | ❌ 连不上 |

原因：ESP32-S3 上 SWD 是 GPIO 位操作（SPI 加速未启用）。

### 6.5 OpenOCD 莫名退出

日志最后一行是 `shutdown command invoked` = **客户端主动关的**：

- CubeIDE 结束调试时点了 **Terminate**（红色方块）→ 它会发 `monitor shutdown`
- 想保留服务：结束会话时用 **Detach** 而不是 Terminate

### 6.6 `keep_alive() was not invoked in the 1000 ms timelimit`

GDB 心跳超时误报，不影响功能，按 §4.3 加 `set remotetimeout 20` 即可。

## 8. 硬件接线

| 信号 | PMOD2 引脚 | ESP32-S3 GPIO | 目标板 |
|---|---|---|---|
| SWDIO | IO7 | GPIO11 | SWDIO / PA13 |
| SWCLK | IO3 | GPIO12 | SWCLK / PA14 |
| GND | GND | — | GND |
| nRESET（建议接） | IO1 | GPIO13 | NRST |

**必接：SWDIO / SWCLK / GND 三根。**
nRESET 可选，但接上之后 CubeIDE 就能用「connect under reset」，下载流程也会稳很多。

> ⚠️ **接电前用万用表确认 3V3 和 GND**。F103 最小系统板这两个丝印相邻，
> 接反等于给 VDD 加 −3.3 V，会直接击穿芯片。
> 更稳妥：目标板自己用 USB 供电，只连 SWDIO / SWCLK / GND。
