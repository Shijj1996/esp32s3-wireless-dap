# 板载状态灯说明（DevKitC-1）

> 适用分支：`DevKitC1`
> 硬件：ESP32-S3-DevKitC-1（N16R8），板载 **WS2812 三色 LED**
> 代码：`main/rgb_led.c` / `main/rgb_led.h`

---

## 1. 为什么要有这个灯

DevKitC-1 **没有屏幕**，而无线调试器最常见的故障恰恰是"看起来在跑，其实卡在某一步"：

- 盒子没上电 / 没连上热点 → 你以为是电脑的问题
- 连上热点了，但 PC 还没挂载 → 你以为盒子挂了
- 已挂载但 OpenOCD 没连上 → 分不清是链路还是 SWD 的问题

有了这个灯，**不用接串口、不用开电脑**，看一眼颜色就知道卡在哪：

| 你看到的 | 含义 | 下一步该做什么 |
|---|---|---|
| 红色慢闪（1Hz） | 没连上 Wi-Fi 热点 | 检查电脑热点是否开启、SSID/密码是否 `ESP32-DAP` / `12345678` |
| 蓝色慢呼吸（2s 一周期） | 已连上热点，等 PC 挂载 | 在电脑上跑 `usbip attach` |
| 绿色**暗** | 已挂载，链路空闲 | 正常，可以启动 OpenOCD / CubeIDE |
| 绿色**亮** | 正在传数据 | 正常，调试/烧录进行中 |
| 常亮红 / 常亮蓝不呼吸 | 异常（固件卡死） | 断电重启；看串口有没有 panic |

## 2. 硬件

| 项目 | 值 |
|---|---|
| 类型 | WS2812（可寻址 RGB，单线） |
| 数据线 | **GPIO48** |
| 数量 | 1 颗 |
| 驱动方式 | RMT 外设，10 MHz 分辨率 |

> ⚠️ **兼容板可能不一样**：官方 DevKitC-1 是 GPIO48，但有些克隆板用的是
> 三颗独立 LED（三个 GPIO）或者别的引脚。如果按默认配置灯不亮，见 §6 排查。

引脚在 `main/dap_configuration.h` 里改：

```c
#define USE_BOARD_RGB_LED   1     // 0 = 完全关闭
#define BOARD_RGB_LED_GPIO  48    // 改成实际引脚
```

## 3. 状态机

LED 任务每 **50 ms** 采样一次，按下面的优先级决定颜色：

```
                 ┌──────────────────────────┐
                 │ 每 50ms 采样一次          │
                 └────────────┬─────────────┘
                              ▼
                 ┌──────────────────────────┐
     否          │ Wi-Fi 连上了吗？          │
        ┌────────┤ (esp_wifi_sta_get_ap_info)│
        │        └────────────┬─────────────┘
        ▼                     │ 是
┌───────────────┐             ▼
│ 红色 1Hz 闪   │   ┌──────────────────────────┐
└───────────────┘   │ 有 USBIP 客户端吗？       │  ← kSock >= 0
                    │ (kSock >= 0)             │
                    └────────────┬─────────────┘
                       否        │        是
                ┌───────────────┐│┌──────────────────────────┐
                │ 蓝色 2s 呼吸  │└┤ 300ms 内有 CMD_SUBMIT？  │
                └───────────────┘ │ (g_usbip_cmd_count 变化) │
                                  └──────┬──────────┬────────┘
                                     是  │          │ 否
                                  ┌──────▼───┐  ┌───▼──────┐
                                  │ 绿 亮140 │  │ 绿 暗 20 │
                                  └──────────┘  └──────────┘
```

### 具体参数

| 状态 | 颜色 (R,G,B) | 时序 |
|---|---|---|
| 未连 Wi-Fi | `(120,0,0)` / `(0,0,0)` | 每 500 ms 翻转一次 |
| 等挂载 | `(0,0,0~95)` | 2 s 一个三角波（呼吸） |
| 已挂载·空闲 | `(0,20,0)` | 常亮 |
| 已挂载·传输中 | `(0,140,0)` | 常亮，数据停止 300 ms 后自动变暗 |
| 开机自检 | 红→绿→蓝→灭 | 每步 250 ms，共 1 s |

"正在传数据"的判定依据是 `g_usbip_cmd_count`——每收到一条 `CMD_SUBMIT` 就自增
（在 `main/usbip_server.c` 的 `handle_submit()` 里）。所以只要 OpenOCD 在读写 SWD，
绿灯就会一直亮着；它停下来 300 ms 后转暗。

## 4. 实现说明

```
main/rgb_led.c
├── rgb_led_init()        创建 RMT 设备 → 自检 → 起任务
├── rgb_led_set_rgb()     单颗灯设色并 refresh
├── self_test()           红→绿→蓝→灭
└── rgb_led_task()        50ms 周期，按上面的状态机刷色
```

依赖的组件：`components/led_strip`（从 espressif/idf-extra-components 拷入，
v2.0.0，只用 `driver`，没有额外 CMake 依赖）。

RGB 顺序：WS2812 本身是 **GRB**，`led_strip_set_pixel(strip, idx, r, g, b)`
内部已经处理好了，直接按 RGB 写即可。

启动日志里能看到两条：

```
I (342) rgb_led: init WS2812 on GPIO48
I (1343) rgb_led: status LED ready        ← 中间这 1 秒就是自检
```

## 5. 关掉它

某些板子没有 WS2812，或者 GPIO48 被别的东西占用时：

```c
// main/dap_configuration.h
#define USE_BOARD_RGB_LED 0
```

关掉后不编译 LED 任务、不占用 RMT 通道，其他功能不受影响。

## 6. 灯不亮怎么办

按顺序排查：

### ① 先看日志确认代码跑了

```
I (342) rgb_led: init WS2812 on GPIO48
```

- **没有这两行** → 宏没开：检查 `dap_configuration.h` 的 `USE_BOARD_RGB_LED`
- **有 `create led strip failed`** → RMT 通道被占用或 GPIO 非法

### ② 自检时是否有颜色

开机 1 秒内应该依次看到 红 → 绿 → 蓝 → 灭。

- **完全不亮** → 引脚不对，或者根本不是 WS2812
- **亮了但颜色不对**（比如该红却绿）→ 芯片是 RGB 顺序而非 GRB，
  这种情况很少见，需要改 `led_strip_set_pixel` 的入参顺序

### ③ 换引脚试

常见候选（不同厂家板子）：

| 引脚 | 出处 |
|---|---|
| **GPIO48** | 官方 ESP32-S3-DevKitC-1 |
| GPIO38 | 部分克隆板 |
| GPIO47 | 部分克隆板 |
| GPIO21 | 少数板子 |

改 `BOARD_RGB_LED_GPIO` 后重新 `build` + `flash` 即可，不用动其他代码。

### ④ 如果是"三个独立 LED"而不是 WS2812

那走的是三个普通 GPIO（每个一路 PWM/电平），`led_strip` 用不了。
这种情况需要：

1. 用 `ledc` 给三个脚各开一路 PWM（参考 IDF 的 `examples/peripherals/ledc`）
2. 把 `rgb_led_set_rgb()` 改成设置三个 LEDC 通道的占空比
3. 其余状态机逻辑（`rgb_led_task`）可以原样保留

> 判断方法：WS2812 只有 **一根数据线 + 电源/地**；
> 三个独立 LED 会有 **三根控制线**。数一下线就知道。

## 7. 和 S3Box 分支的关系

| 分支 | 指示方式 |
|---|---|
| `S3Box` | 板载 **2.4" LCD 状态屏**（`main/display.c`），没有用这颗灯 |
| `DevKitC1` | 没有屏幕，改用**这颗 WS2812**（`main/rgb_led.c`） |

两个模块互相独立，都由 `main/dap_configuration.h` 里的开关控制，
理论上可以同时启用（如果以后有既带屏又带灯的板子）。

## 8. 历史问题：灯和实际状态不同步（已修）

早期版本会出现这些现象，根因都在 TCP 层的状态维护上：

| 现象 | 根因 | 修复 |
|---|---|---|
| 挂载后灯还是蓝色，过很久才变绿 | 上一个超时请求留下的半开连接占住了 `accept()`，真正的挂载排在 backlog 里等 20 秒 | `ATTACHING` 状态 5 秒没收到请求就踢掉 |
| detach 后灯不变回蓝色 | `close(kSock)` 之后没有把 `kSock` 复位成 -1 | 关闭后 `kSock=-1; kState=ACCEPTING` |
| 热点关了再开，灯直接变绿 | 同上（`kSock` 还是旧值） | 同上 |
| 热点掉过一次后，**ping 通但 3240 连不上** | socket/bind/listen 失败直接 `break` 出外层循环，**TCP 任务永久退出** | 改为等 1 秒重试；`accept()` 改 `select(200ms)`，掉线能及时感知 |
| 反复掉线后彻底连不上 | 重建监听 socket 时没关旧的，fd 泄漏（上限 10 个） | 退出 accept 循环时 `close(listen_sock)` |

顺带一提：因为"一次只服务一个客户端"，**挂载期间跑 `usbip list` 会卡 20 秒**（新连接排在 backlog），
这是正常现象，见 `docs/手动操作手册.md` §2 开头的说明。
