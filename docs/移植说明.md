# 移植说明（ESP32-S3 → ESP32-S3-DevKitC-1）

本文记录这个工程**移植到 ESP32-S3 实际改了哪些东西**，以及**换到 ESP32-S3-DevKitC-1 板卡需要做什么**。

---

## 1. 工程来源与结构

上游：[badboyhuan/wireless-esp32-dap](https://github.com/badboyhuan/wireless-esp32-dap)
（再上游 windowsair/wireless-esp8266-dap）

上游只支持 ESP8266 / ESP32 / ESP32-C3，基于 IDF 4.4。本仓库把它搬到 **ESP32-S3 + ESP-IDF v5.5.4**。

```
wireless-dap-s3-box/
├── main/                       业务层（几乎全部是板级/芯片级移植点）
│   ├── main.c                  任务创建：TCP 服务、DAP、UART 桥
│   ├── wifi_configuration.h    ★ 板级配置：STA/SoftAP、IP、SSID
│   ├── wifi_handle.c           ★ Wi-Fi 事件（IDF 5.x 新 API）
│   ├── tcp_server.c            ★ USBIP over TCP 的接收循环（含流式组包）
│   ├── usbip_server.c          USBIP 协议分发（stage1/stage2）
│   ├── DAP_handle.c            DAP 命令队列、应答配对（读请求 FIFO）
│   ├── dap_configuration.h     ★ USE_WINUSB / USE_SPI_ACCEL 等编译开关
│   └── uart_bridge.c           串口桥（可选功能）
├── components/
│   ├── USBIP/                  USBIP 协议 + USB 描述符（★ 端点布局在这里）
│   ├── DAP/                    CMSIS-DAP 核心 + ★ DAP_config.h（引脚）
│   ├── elaphureLink/           elaphureLink 兼容层
│   └── kcp/                    KCP 传输（未使用）
├── tools/                      上位机脚本
├── docs/                       文档
└── build.ps1                   ★ 封装 idf.py（写死本机工具链路径）
```

标 ★ 的是换板子时**真正要动**的地方。

## 2. 移植到 ESP32-S3 改了哪些

### 2.1 构建系统

上游用 `export.ps1` 设环境，本机不可用，改成 `build.ps1` 显式写死：

| 变量 | 值 |
|---|---|
| `IDF_PATH` | `D:\ESP32_SDK\esp32s3_v554\.espressif\v5.5.4\esp-idf` |
| `IDF_PYTHON_ENV_PATH` | `C:\Espressif\tools\python\v5.5.4\venv` |
| 工具链 | `C:\Espressif\tools\xtensa-esp-elf\esp-14.2.0_20260121\xtensa-esp-elf\bin` |

### 2.2 GPIO / 引脚适配（`components/DAP/config/DAP_config.h`）

新增 `CONFIG_IDF_TARGET_ESP32S3` 分支，提供：

- `PIN_SWDIO` / `PIN_SWDIO_MOSI` / `PIN_SWCLK` / `PIN_nRESET`
- `PORT_JTAG_SETUP()` / `PORT_SWD_SETUP()` / `PORT_OFF()`
- `PIN_SWDIO_IN/OUT`、`PIN_SWDIO_OUT_ENABLE/DISABLE`
- `PIN_SWCLK_TCK_SET/CLR`

S3 默认引脚：

```c
#define PIN_SWDIO      11    // FSPID，SIO 模式与 MOSI 同脚
#define PIN_SWDIO_MOSI 11
#define PIN_SWCLK      12    // FSPICLK
#define PIN_TDO         9    // 未接线，仅为编译通过
#define PIN_TDI        10
#define PIN_nTRST      14
#define PIN_nRESET     13
```

### 2.3 GPIO 低层操作（`components/DAP/include/gpio_op.h`）

新增 S3 分支，直接写寄存器（SWD 位操作的性能关键路径）：

```c
GPIO.out_w1ts / GPIO.out_w1tc        // <32 脚
GPIO.out1_w1ts.val / out1_w1tc.val   // >=32 脚
GPIO.in / GPIO.in1.val               // 读电平
```

### 2.4 SWD 时序延时（`components/DAP/include/DAP.h`）

新增 S3 的 `PIN_DELAY_SLOW()` 汇编实现（LX7 上 `ADDI.N` 编码受限，改用 `ADDI`）：

```c
__asm__ volatile("l_PINDELAYSLOW%=:"
                 "ADDI %[time], %[time], -1;"
                 "BNEZ %[time], l_PINDELAYSLOW%=;"
                 : [time] "+r"(delay));
```

### 2.5 时钟换算（`components/DAP/source/DAP.c`）

```c
#define BUS_CLOCK_FIXED 240000000U   // S3 主频 240 MHz
```

> ⚠️ 这个值必须等于实际 CPU 频率。原来写的 80 MHz 会让**实际 SWD 时钟是请求值的 3 倍**。

### 2.6 SPI 加速（`components/DAP/source/spi_switch.c`）

S3 上 **未启用**（`USE_SPI_ACCEL == 0`），`DAP_SPI_Init()` 是空函数。
`DAP_SPI_Deinit()` 负责把引脚切回 GPIO，并**配置 SWDIO 为开漏**：

```c
// SWCLK: 推挽输出
gpio_ll_od_disable(&GPIO, 12);
GPIO.enable_w1ts = (0x01U << 12);

// SWDIO: 开漏 + 输入使能 + 立即释放（关键！）
gpio_ll_od_enable(&GPIO, 11);
GPIO.enable_w1ts = (0x1U << 11);
gpio_ll_input_enable(&GPIO, 11);
GPIO.out_w1tc = (0x1U << 11);
GPIO.out_w1ts = (0x1U << 11);
```

> ⚠️ SWDIO 必须是**开漏**。推挽输出时目标拉不低电平，读回来永远是 1，
> 表现为 `Error connecting DP: cannot read IDR`。

### 2.7 Wi-Fi（`main/wifi_handle.c` + `main/wifi_configuration.h`）

- IDF 5.x 事件 API（`esp_event_handler_instance_register`）
- 新增 `esp_wifi_set_country_code("CN", true)`（否则扫不到 12/13 信道）
- 静态 IP：`esp_netif_dhcpc_stop()` + `esp_netif_set_ip_info()`
- 模式：`USE_SOFTAP 0`（STA 连电脑热点）

### 2.8 USB 描述符（`components/USBIP/usb_descriptor.c`）

端点布局改成 **CMSIS-DAP v2 标准**（OpenOCD 硬性要求）：

| 顺序 | 端点 | 用途 |
|---|---|---|
| endpoint[0] | `0x02` Bulk OUT | 命令（主机→设备） |
| endpoint[1] | `0x81` Bulk IN | 应答（设备→主机） |
| endpoint[2] | `0x83` Bulk IN | SWO trace |

> OpenOCD 的 `cmsis_dap_usb_bulk.c` 会检查 `endpoint[0]` 必须是 bulk OUT、
> `endpoint[1]` 必须是 bulk IN，否则直接 `skipping interface 0`。

### 2.9 USBIP 传输层（`main/tcp_server.c` / `main/usbip_server.c` / `main/DAP_handle.c`）

这几处不是"移植"，是**修 bug**，但会跟着代码走，必须保留：

1. **流式组包**：`recv()` 是字节流，必须按 `data_length` 攒够一个完整的 stage2 包再分发
2. **应答头部整头字节序转换**（`seqnum/devid/ep` 一个都不能漏）
3. **OUT 应答要回报真实 `actual_length`**
4. **读请求 FIFO 挂起**：主机流水线提交，读常常先于写到达，不能直接回 0 字节
5. **DAP 任务钉核 + 加大栈**：`xTaskCreatePinnedToCore(..., 6144, ..., 20, ..., 1)`

### 2.10 板载 LCD 状态屏（`main/display.c` + `components/esp_lcd_ili9341`）

新增功能，不属于上游。BOX-3 正面那块 2.4" 320x240 屏用来显示运行状态。

引脚直接从官方 `esp-box` BSP（`esp-box-3.h`）抄，不是猜的：

| 信号 | GPIO | 说明 |
|---|---|---|
| MOSI (DATA0) | 6 | SPI3 |
| SCLK (PCLK) | 7 | 40 MHz |
| CS | 5 | |
| DC | 4 | |
| RST | 48 | 高电平有效（`reset_active_high = 1`） |
| 背光 | 47 | LEDC 5 kHz PWM |

驱动：`components/esp_lcd_ili9341`（从 esp-box 的 managed_components 拷入，
去掉 `cmake_utilities` 依赖，手动补 `ESP_LCD_ILI9341_VER_*` 宏）。

字库：`main/font_pingfang14.c`，从 esp-box 示例的 LVGL 字体（`ui_font_PingFangEN14.c`）
提取成独立 4bpp 点阵，**没有引入 LVGL**。

三个必须记住的坑：

1. **字节序**：RGB565 是 16 位，面板按大端接收、ESP32 内存小端 → 推屏前必须交换高低字节
2. **不能就地交换**：复用缓冲会重复交换，画出来是明暗相间的条纹
3. **必须等 DMA 传完**：`esp_lcd_panel_draw_bitmap()` 只是排队就返回，
   立刻复用缓冲会导致撕裂/重影 → 用 `on_color_trans_done` + 信号量同步

无屏板子（DevKitC-1）把 `main/dap_configuration.h` 里的 `USE_BOX3_DISPLAY` 置 0 即可整体裁掉。

改布局可以用 `tools/render_preview.py` 在 PC 上出预览图，不用烧板子。

## 3. 换到 ESP32-S3-DevKitC-1 要做什么

### 3.1 先确认买的型号

| 型号 | Flash | PSRAM | 要不要改 sdkconfig |
|---|---|---|---|
| **N16R8** | 16 MB | 8 MB | ❌ 不用改，和现在完全一致 |
| N8R8 | 8 MB | 8 MB | ✅ 改 Flash 大小 |
| N8（无 R） | 8 MB | 无 | ✅ 改 Flash 大小 |

**本工程当前不用 PSRAM**（`CONFIG_SPIRAM is not set`），所以有没有 PSRAM 都能跑。

当前 sdkconfig：

```
CONFIG_ESPTOOLPY_FLASHSIZE="16MB"
CONFIG_ESPTOOLPY_FLASHMODE="dio"
CONFIG_ESPTOOLPY_FLASHFREQ="80m"
CONFIG_ESP32S3_DEFAULT_CPU_FREQ_MHZ=240
```

如果是 8 MB 版本，改 `CONFIG_ESPTOOLPY_FLASHSIZE="8MB"` 即可
（app 分区在 `0x10000`，长度 1.5 MB，8 MB 完全够）。

### 3.2 引脚：可以直接沿用，也可以改

DevKitC-1 是排针板，**GPIO11 / GPIO12 / GPIO13 都引出了**，所以：

**方案 A（推荐，零代码改动）**：按现有引脚接线

| 信号 | DevKitC-1 排针 | 说明 |
|---|---|---|
| SWDIO | **IO11** | 与 GPIO11 一致 |
| SWCLK | **IO12** | 与 GPIO12 一致 |
| nRESET（可选） | **IO13** | 与 GPIO13 一致 |
| GND | GND | 必接 |

**方案 B**：想用别的脚，改 `DAP_config.h` 里 S3 分支的 4 个宏即可：

```c
#define PIN_SWDIO      11
#define PIN_SWDIO_MOSI 11
#define PIN_SWCLK      12
#define PIN_nRESET     13
```

改完重新编译烧录。**注意**：
- 避开 GPIO0（BOOT）、GPIO45/46（strapping）、GPIO19/20（USB D-/D+）、GPIO43/44（UART0）
- 如果将来想启用 SPI 加速，SWDIO 必须落在 **FSPID**、SWCLK 必须落在 **FSPICLK**（S3 上是 GPIO11/GPIO12）

### 3.3 烧录方式

DevKitC-1 有两个 USB 口：

| 口 | 丝印 | 用途 |
|---|---|---|
| USB-UART | `UART` | **烧录 + 串口日志**（板载 CP2102/CH343） |
| USB-OTG | `USB` | 原生 USB（本工程不用） |

用 `UART` 口，`build.ps1 -p COMx flash` 即可。COM 号看设备管理器。

### 3.4 和现在这块 Waveshare 板的差异

| 项目 | Waveshare ESP32-S3-Pico/Dock | DevKitC-1 |
|---|---|---|
| 接线方式 | PMOD2 排针（IO1/IO3/IO7…） | 普通 2.54 排针，**直接用 GPIO 编号** |
| 串口芯片 | CH343P | CP2102 或 CH343（视批次） |
| SD 卡槽 | 有（**GPIO13 冲突，不能插卡**） | 无，没有这个坑 |
| RGB LED | 有 | GPIO48（部分版本 GPIO38） |
| 供电 | 3V3 输出引脚 | 3V3 输出引脚 |
| 固件差异 | — | **无**（都是 ESP32-S3，同样的二进制） |

**结论：DevKitC-1 反而更省事**——没有 SD 卡槽冲突，引脚直接按编号接。

### 3.5 移植检查清单

- [ ] 确认型号（N16R8 还是 N8），必要时改 `CONFIG_ESPTOOLPY_FLASHSIZE`
- [ ] **无屏板子：把 `main/dap_configuration.h` 的 `USE_BOX3_DISPLAY` 改成 0**
      （DevKitC-1 没有 LCD，不关掉会白占 SPI3 和 40KB 缓冲）
- [ ] 按 GPIO11/12/13 + GND 接线（或用方案 B 改引脚宏）
- [ ] `build.ps1 build` 编译通过
- [ ] `build.ps1 -p COMx flash` 烧录
- [ ] 串口看到 `wifi: wireless DAP ready at 192.168.137.50:3240`
- [ ] 电脑上 `usbip list -r 192.168.137.50` 能看到 `1-1`
- [ ] `usbip attach ... --receive-mode low-latency` 成功
- [ ] `usbip port` 显示 `Port 01: device in use`
- [ ] 用 `tools\stm32cubeide-dap.ps1 -Mode flash` 能烧 STM32

## 4. 已知限制（务必知道）

| 能力 | 状态 |
|---|---|
| 烧录 STM32 固件 | ✅ 稳定（写 3 KiB/s，校验 12 KiB/s） |
| 读 Flash / 读内存 / halt / resume | ✅ 稳定 |
| **CubeIDE 交互式调试（断点/单步）** | ⚠️ **不稳定** |
| SWD 时钟上限 | 300 kHz 可靠，700 kHz 极限，800 kHz 失败 |

交互式调试失败的根因：CubeIDE 的 `load` 会走 OpenOCD 的 **`reset init`**，
而 reset-init 在这条「Wi-Fi + usbip + 位操作 SWD」链路上会让 DP 失联
（`Error connecting DP: cannot read IDR`）。

后续可尝试的方向：
1. 接 nRESET（GPIO13 → 目标 NRST），启用 connect-under-reset
2. 让 DAP 在检测到复位后自动重发 JTAG→SWD 切换序列（`SWJ_Sequence` 0xE79E）
3. 启用 SPI 加速提高时序余量（`USE_SPI_ACCEL`）
